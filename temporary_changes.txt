# Temporary Changes in slotopol_server

This file documents temporary modifications made for development and testing purposes. These changes should be reverted before deploying to a production environment.

## 1. Bypassed ALbooker Access Check for /prop/wallet/add

**File:** `api/props.go`

**Description:** The access control check requiring `ALbooker` permission for the `ApiPropsWalletAdd` function has been commented out. This allows any authenticated user to add coins, facilitating front-end testing of the "Add Coins" button without needing to set up administrative user accounts.

**Lines affected (approximately):** Lines 140-143 (within `func ApiPropsWalletAdd`)

**How to revert:**
Uncomment the following lines within the `ApiPropsWalletAdd` function:
```go
	var admin, al = MustAdmin(c, arg.CID)
	if al&ALbooker == 0 {
		Ret403(c, AEC_prop_walletadd_noaccess, ErrNoAccess)
		return
	}
```
And revert the changes made to the `BankBat` calls (lines 153 and 154) to use `admin.UID` instead of `arg.UID`:
Line 153:
`go BankBat[arg.CID].Add(cfg.XormStorage, arg.UID, admin.UID, props.Wallet+arg.Sum, arg.Sum)`
Line 154:
`} else if err = BankBat[arg.CID].Add(cfg.XormStorage, arg.UID, admin.UID, props.Wallet+arg.Sum, arg.Sum); err != nil {`

**Reason for change:** Facilitate testing of "Add Coins" functionality.

## 2. Mobile-Friendliness Adjustments and SYMBOL_HEIGHT Mismatch

**File:** `static/slot-game/style.css` and `static/game-launcher/script.js` (implicit)

**Description:** Responsive CSS styles have been added to `static/slot-game/style.css` using media queries (`@media (max-width: 768px)`) to make the slot machine layout mobile-friendly. This involves reducing `SYMBOL_HEIGHT`, `.reels` height, `.reel` width, and adjusting font sizes.

**Potential Mismatch:** The `SYMBOL_HEIGHT` constant in `static/game-launcher/script.js` (currently `150`) is a fixed JavaScript value used for animation calculations. In the mobile view, the CSS `SYMBOL_HEIGHT` is set to `75px`. This discrepancy means the JavaScript animation calculation (`targetSymbolOffset = offsetBeforeTarget * SYMBOL_HEIGHT`) will still use `150` for its internal logic, which might lead to visual inconsistencies during the reel spin animation on mobile devices, as the CSS visual size and JS internal calculation size won't match.

**How to fully resolve (requires further development):**
To completely resolve this, the `SYMBOL_HEIGHT` constant in `script.js` would need to be dynamically determined at runtime based on the actual rendered size of a symbol (e.g., by reading its computed style from the DOM) or by using CSS variables that can be accessed via JavaScript and updated by media queries.

**Reason for change:** Improve user experience on mobile devices.
